# ADR 0000: Decision title

- Status: Proposed
- Date: Date of the decision
- Decision owners: Public project role or component owner
- Supersedes: None
- Superseded by: None

## Context

Describe the user need, constraints, current behavior, threat boundaries, and why a durable decision
is required. Separate verified repository evidence from assumptions and future design.

## Decision

State the chosen behavior precisely, including versioning, ownership, enforcement points, and what
is explicitly excluded.

## Security and privacy consequences

Describe assets, attacker capabilities, data collection, access, retention, deletion, abuse cases,
new controls, residual risk, and affected security invariants. Do not include secrets, live
thresholds, personal incident details, or exploit data under embargo.

## Alternatives considered

List credible alternatives, including a simpler or lower-risk option, and explain why each was not
selected. Record important disagreement.

## Migration and rollback

Explain stored-data, credential, protocol, deployment, and user-communication changes. Define how to
disable, revert, supersede, or forward-fix the decision without weakening security controls.

## Verification

List positive, negative, compatibility, concurrency, recovery, privacy, and operational evidence
needed before the implementation can be called complete.

## References

Link canonical public plans, contracts, threat/privacy documents, prior ADRs, and external
standards. Do not rely only on a pull-request conversation.
