## Current support declaration

Zero providers are supported or enabled for new AgentAccounts by default. The table above records
the exact local evidence and blocking gaps. Codex test promotion inside disposable fixtures does not
change this declaration.

## Admission requirements

One row may become `supported` only when the same reviewed revision includes:

1. exact admitted agent and local-schema versions or an immutable schema digest;
2. fixed safe roots plus link/reparse/device/alternate-stream/size/encoding bounds;
3. a closed provider-neutral reader output;
4. documented aggregate-versus-component and repeated/cumulative deduplication;
5. exact UTC-day derivation and bounded backfill behavior;
6. a stable opaque account-domain rule or explicit create/attach requirement;
7. an immutable accounting revision, competitive scope, and overlap exclusions;
8. positive, boundary, corrupt, drift, race, and prohibited-data sentinel fixtures;
9. clean-machine discovery, batch pairing, first/repeat sync, multi-device account/day, weekly rank,
   last-good snapshot, and finalization evidence;
10. supported connector/platform versions with install, update, uninstall, credential-store,
    checksum, SBOM, provenance, signature, and protected artifact evidence; and
11. an explicit reviewed support declaration in registry, database, documentation, and release
    metadata.

Plausible paths, public API fields, MCP compatibility, screenshots, another provider's accounting
rules, synthetic-only fixtures, or a local source build are insufficient.

## Reader and privacy rules

A reader may emit only the closed provider ID, opaque bounded candidate evidence, safe private
label, UTC dates, canonical cumulative decimal totals, and version identifiers. It must not export
or log prompts, conversations, code, tool output, repository names, local paths, email, login,
display name, API/OAuth tokens, model, price, plan, raw records, or provider-shaped components.

Unknown usage-bearing schema, ambiguous aggregate/component relationships, unsafe account domains,
partial parse, timezone ambiguity, or overlap invalidates the affected candidate/day. The connector
does not estimate, silently skip required records, normalize through another tokenizer, or infer
identity from mutable personal data.

## Change policy

Accounting semantics are immutable per revision. A semantic change creates a new revision for new
accounts/seasons; it never reinterprets accepted history. Schema drift fails closed. An emergency
block marks the exact combination disabled without relabeling Community data, widening a role,
restoring a legacy route, or falling back to another provider.
