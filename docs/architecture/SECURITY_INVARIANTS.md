# Security invariants

These are active public design commitments under
[ADR 0076](../decisions/0076-clean-agent-account-provider-reported-token-ranking.md). Each
implementation maps them to an owner, an enforcement point, and automated negative tests. Acceptance
of the design is not implementation evidence; current proof remains in
[IMPLEMENTATION_STATUS.md](../IMPLEMENTATION_STATUS.md).

| VR-PUBLIC-001        | Every tracked artifact is safe for immediate public disclosure and contains no working secret, personal data, private log, or local path.                                                                                                                    | Repository and CI                      | Public-file, history, staged-diff, synthetic-fixture, and secret-pattern checks                                                             |
| VR-IDENTITY-001      | One immutable GitHub numeric user ID has at most one profile. Login, handle, display name, and email are not identity keys; repeated OAuth cannot create another profile; anonymous profiles do not exist.                                                   | Web/Auth and Database                  | OAuth state/PKCE, unique-ID concurrency, immutable-ID, repeat-login, and no-anonymous-state tests                                           |
| VR-AUTH-001          | GitHub resolves identity only. Initial enrollment requires a primary passkey, and fresh action-bound passkey step-up protects batch device approval, recovery changes, account/device reactivation or disconnection, and profile deletion.                   | Web/Auth                               | OAuth, WebAuthn origin/RP/challenge/replay, session rotation, CSRF, and critical-action tests                                               |

| VR-ORIGIN-001        | Ingest accepts public traffic only when it carries a fresh exact-path/body-bound proof from the configured Edge; caller-supplied origin authority is rejected.                                                                                               | Edge and Ingest                        | Direct-origin, path/body tamper, key rotation, atomic replay-race, encoding, and clock-skew tests                                           |
| VR-DATA-001          | Auth, Web read, Ingest, Jobs, Admin, and migration capabilities use separate least-privileged database roles; runtime roles own no schema object and cannot run arbitrary SQL.                                                                               | Database                               | Role bootstrap, forced RLS, ownership/grant, widened-login denial, reset-before-reuse, and adapter probes                                   |

## Implementation evidence boundary

ADR 0076 makes the table above authoritative for the clean replacement. Until each implementation
slice and its negative tests land:

- the corresponding row is a required target, not a claim that the old runtime satisfies it;
- old CodexSource, `community_v1`, `/v1/community/*`, anonymous-onboarding, and 43-revision evidence
  must not be cited as proof of the new row;
- a provider remains `recognized` or `disabled` until its exact reader and accounting revision
  evidence exists;
- Community remains unverified even after device signatures and exact server accounting;
- repository-local tests do not prove hosted release, signing, deployment, production credentials,
  monitoring, capacity, provider correctness, or real-user behavior.

`docs/IMPLEMENTATION_STATUS.md` records the current proof boundary and is updated with each logical
implementation commit.

## Change policy

Changing an invariant requires:

1. a public ADR describing motivation and alternatives;
2. an updated threat model and abuse-case analysis;
3. explicit maintainer and security review;
4. updated negative tests before the behavior ships;
5. migration and rollback instructions where stored data or credentials are affected.

Production thresholds, secrets, personal incident details, and exploit data that would materially
increase active risk belong in protected operational systems, not this document.
